# Security and Privacy

**Status:** Planned rules, not yet tested · 2026-10-26

I want this to be a helper, not a program that takes over someone's computer or online accounts. These are the rules I intend to build into the application itself. Telling an AI not to do something is not enough.

## What it can do

| Action | Rule |
| --- | --- |
| Answer questions and explain steps | Allowed |
| Look at the selected screen or current webpage | Only when the user asks; avoid sensitive pages |
| Open Pictures, Documents, Downloads, or approved programs | Allowed from a fixed list |
| Search online for general public information | Optional, off by default; send only a cleaned-up question |
| Open websites, click links or buttons, type into forms, or submit anything | **Not allowed** |
| Make purchases, change accounts, or approve transactions | **Not allowed** |
| Read, save, or say passwords from a vault | **Not allowed** |
| Delete or move files, install programs, change security settings, or run arbitrary commands | **Not allowed** |
| Send private screenshots, webpage contents, or recordings to cloud AI services | **Not allowed** |

The password manager may fill passwords in the browser, but the helper will not connect to its vault.

## What could go wrong

- **A website gives the AI instructions.** Websites are information to read, not instructions to follow. The helper must have no browser-control or unrestricted command tools.
- **A screen contains private information.** Screen access needs an obvious on/off state and permission each time it is used. Banking, health, login, and payment screens should not be captured by default. I cannot assume sensitive details can always be hidden reliably.
- **The AI requests the wrong action.** The application should run with normal user permissions and accept only approved destinations, not paths or commands generated by the AI.
- **The AI gives the wrong advice.** It needs to say when it is unsure, give one step at a time, and check whether the user is ready to continue.
- **Information leaves the computer.** A local model does not automatically mean every other component is private. I need to check network traffic, dependencies, logging, and any optional internet search.
- **Someone misuses remote help.** A human-help option must never grant unattended access. Any remote session needs the person's permission and separate confirmation.

By default, the application should not save screenshots, voice recordings, passwords, account details, or private documents. None of that belongs in the public GitHub repository.

## Before I let someone use it

I'll test these safeguards on both operating systems:

- [ ] Disallowed actions remain blocked, including when a webpage tries to give the AI instructions.
- [ ] Approved folder and program shortcuts cannot be used to open something else.
- [ ] Screen and voice information stays local and out of logs.
- [ ] Stop and screen-permission controls work as expected.
- [ ] The local model is not exposed to other devices, and failures do not bypass restrictions.
- [ ] Tests use fake accounts and sample webpages rather than real personal information.

Each user will decide whether to install the helper and when to share a screen. Only test results or screenshots that are synthetic or separately approved and anonymized should be published.

These are design requirements. They are not claims that the application is already secure. I'll record the results in the [test plan](Roadmap_and_Test_Plan.md).
